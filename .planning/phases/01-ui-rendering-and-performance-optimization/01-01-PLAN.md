<objective>
Optimize UI rendering and frame pacing for the Now Playing player screen. Eliminate unnecessary recomposition passes during playback progress ticks and zero heap allocations inside the MeshGradient / wave drawing loops.
</objective>

<execution_context>
- Codebase map: `.planning/codebase/ARCHITECTURE.md`, `CONVENTIONS.md`, `STACK.md`
- Context: `.planning/phases/01-ui-rendering-and-performance-optimization/01-CONTEXT.md`
- Research: `.planning/phases/01-ui-rendering-and-performance-optimization/01-RESEARCH.md`
</execution_context>

<context>
`NowPlayingScreen.kt` and `PlayerControls.kt` represent the most visually rich surface in UMtify. Because playback progress updates occur multiple times per second, passing raw timestamps or unstable objects causes whole-tree recomposition. In addition, `MeshGradient.kt` executes per-frame rendering that currently allocates object lists inside `Canvas { ... }`.
</context>

<tasks>
<task id="01-01-01">
  <title>Decompose PlayerControls and isolate progress recomposition</title>
  <read_first>
    - sharedUi/src/jvmSharedMain/kotlin/com/music/bitchord/ui/player/NowPlayingScreen.kt
    - sharedUi/src/jvmSharedMain/kotlin/com/music/bitchord/ui/player/PlayerControls.kt
    - sharedUi/src/jvmSharedMain/kotlin/com/music/bitchord/ui/player/WavySeekBar.kt
  </read_first>
  <action>
    1. Ensure `PlayerControls.kt` progress parameters are supplied via lambda providers (`() -> Float`, `() -> Long`) instead of naked primitives, following the pattern established in `WavySeekBar.kt`.
    2. Mark player state models passed between `NowPlayingScreen` and `PlayerControls` with `@Immutable` / `@Stable` so Compose skips unchanged subtrees during state updates.
    3. Ensure click callbacks (`onPlayPause`, `onNext`, `onPrevious`, `onSeek`) are remembered or function references that do not break memoization across frames.
  </action>
  <verify>
    Run `./gradlew :sharedUi:jvmTest` to ensure all player UI and clock tests pass cleanly without regression.
  </verify>
  <done>
    `NowPlayingScreen` and `PlayerControls` do not recompose the entire view tree when the playback position ticks.
  </done>
</task>

<task id="01-01-02">
  <title>Zero draw-phase allocations in MeshGradient and tune animation pacing</title>
  <read_first>
    - sharedUi/src/jvmSharedMain/kotlin/com/music/bitchord/ui/player/MeshGradient.kt
  </read_first>
  <action>
    1. In `MeshGradient.kt`, pull the `anchors` list allocation outside the `Canvas { ... }` draw lambda into a cached constant or remember block so new `Offset` objects are not created on every frame.
